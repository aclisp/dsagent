# 私聊 Web UI

状态：已完成并由用户验收。

## 产品定位

- 新页面是用户与数字员工进行私聊的入口。
- 目标是让非技术用户感觉正在和真人聊天。
- 新页面可完整交互，不是只读页面。
- 新页面与诊断页面共享同一个 Session。
- 新页面仍展示共享 Session 返回的全部消息，不做来源过滤。
- 新页面发起的 Turn 不自动投递到 IM 群聊。
- 现有诊断页面继续展示全部底层事件和技术信息。

## 页面与路由

- `/chat/:workspaceId`：新的私聊页面。
- `/debug/:workspaceId`：现有诊断页面。
- `workspaceId` 继续作为访问凭证。
- 页面路由由服务端先校验 `workspaceId`；未知 workspace 返回 404。
- 新页面不显示 `workspaceId`、`sessionId`、模型或 Provider。
- 新页面不提供进入 `/debug` 的链接。
- 不保留 `/chat` 原诊断行为的兼容入口。

## 固定身份

- 姓名固定为 Steve Code。
- 头像固定使用 `/favicon.png`。
- 浏览器标题为“与 Steve Code 私聊”。
- 姓名和头像直接写在 `chat.html`。
- 不支持配置或编辑身份。
- 不显示“AI 助手”等技术标签。

## 视觉与布局

- 使用 Light Scheme。
- 移动优先的单列聊天布局。
- 顶部固定显示头像、Steve Code 和状态。
- 中间为可滚动消息列表。
- 底部固定输入区。
- 桌面端聊天区域最大宽度约 760px，居中展示。
- iPhone 竖屏占满动态视口。
- 适配刘海、地址栏、软键盘和底部安全区域。
- 输入、上传、发送/停止和弹窗操作等主要触摸控件至少 44px。
- 不做侧边栏、设置、菜单、会话列表、PWA 或离线缓存。

## 视觉语言

- 页面使用浅冷灰背景和白色聊天区域。
- Steve Code 使用左侧白色气泡。
- 用户使用右侧柔和蓝色气泡。
- Steve Code 每组连续消息的第一条显示圆形头像。
- 状态和时间使用中性灰色。
- 空闲使用绿色圆点；处理或停止时使用蓝色圆点；连接中或断线时使用灰色圆点。
- 不使用渐变、毛玻璃、大型插画或强烈装饰。

## 消息来源与呈现范围

当前 Feature 的消息来源只有：

- 普通用户消息。
- Steve Code 消息。

为让共享 Session 可读，本 Feature 同时已经实现以下过程呈现；它们不是新的消息来源：

- 工具调用折叠为“工作过程”卡片。
- `notify` 和错误、警告显示为系统消息。
- Thinking、Compaction 和 Working Message 显示在顶部状态。
- Compaction Summary 显示为记忆整理提示。
- 授权请求显示为交互弹窗。

AI_WORKER 后续接入后：

- 页面仍显示群聊和定时任务产生的共享消息。
- 跨页面接收的用户消息按 Turn ID 关联和去重；不同 Turn 即使文字完全相同也分别显示，自动重连重放同一 Turn 时不重复追加。
- 群聊消息可以显示为“群聊 · 姓名”。
- 定时任务可以显示为居中事件卡。
- 这些来源适配不在当前 Feature 实现。

## 消息内容

- 所有 Assistant 自然语言过程都显示为 Steve Code 气泡。
- 不只显示最后一段 `completed output`。
- 用户消息始终按纯文本展示。
- Steve Code 消息使用 Marked 渲染 Markdown。
- 支持段落、标题、列表、引用、强调、代码、链接和表格。
- 使用本地提供的 Marked ESM，不依赖 CDN。
- 不增加 HTML 清洗或脚本过滤。
- 不增加代码语法高亮。
- 链接在当前页面打开。
- 正文中可识别的 workspace 文件路径和上传附件转换为 `/share/:workspaceId/...` 可点击链接；代码块中的原始内容不做路径增强。

## 工具调用

- 每个 Turn 只显示一个默认折叠的“工作过程”。
- 运行时显示“正在处理 · N 项操作”。
- 正常完成显示“已完成 N 项操作”。
- 中止显示“已停止 · N 项操作”。
- 只有 Turn 最终失败才显示“未能完成 · N 项操作”；单次工具调用失败后 Agent 继续处理并最终完成时，仍显示“已完成 N 项操作”。
- 用户拒绝授权显示“未获授权 · N 项操作”，不误报为“未能完成”。
- 展开后只显示中文化步骤，例如“读取文件”“修改文件”“执行命令”。
- Turn 最终完成或历史终态无法确认时，不用红色标记已经被 Agent 恢复的局部工具错误。
- 不显示工具参数、命令内容、原始结果、错误堆栈或内部工具名。
- 历史中最后一次工具调用之后存在正常 Assistant 文本时显示“已完成”；缺少可确认最终结果的文本时显示中性的“工作过程 · N 项操作”，不根据单次工具错误推断整个 Turn 失败。
- 完整技术过程只在 `/debug` 查看。

## 运行状态

顶部姓名下方显示：

- 连接中：正在连接
- 断线：正在重新连接
- 空闲：在线
- 普通工作：正在处理 · 12 秒
- Thinking：正在思考 · 12 秒
- Compaction：整理记忆 · 12 秒
- 正在中止：正在停止

规则：

- 从 `Working (12s · esc to interrupt)` 中提取秒数。
- 不显示英文 Working 或 `esc to interrupt`。
- 消息区显示三个跳动圆点，直到第一段回复文本出现。
- Thinking 和 Compaction 结束后恢复“正在处理”。
- Turn 结束后恢复“在线”。
- 连接中或断线时输入区不可用；连接恢复且空闲后自动聚焦输入框。

## 时间与历史

- 每条消息显示本地小时和分钟。
- 跨日期显示“今天”“昨天”或具体日期分隔。
- 页面启动时一次加载 `messages` 返回的全部当前上下文。
- 不做分页和加载更多。
- 页面启动时加载到的完整历史作为本次页面的 DOM 保留基线。
- 页面长时间运行并继续产生大量消息时，按完整 Turn 分批收起最早的对话，避免消息 DOM 无上限增长；通常以最近 100 个 Turn 为保留目标，并额外保留一段缓冲后再批量回收。
- 同时使用顶层时间线项数量作为保护阈值；单个 Turn 产生大量消息或过程项时可以进一步前移回收边界，但不会拆开当前运行中的 Turn。
- 如果启动时的当前上下文本身超过默认保留量，以启动时的数量为最低保留量，不在初始化阶段裁剪。
- 回收只删除浏览器中的旧 DOM，不修改 Session；顶部显示较早对话已收起的提示，手工刷新后重新以当前 Session 历史为权威结果。
- 当前运行中的 Turn 不会被拆开；用户正在向上查看即将被收起的历史时延迟回收。
- 默认滚动到最新消息。
- Compaction Summary 显示为“较早的对话已整理为记忆”，不显示原始摘要。
- 已被裁剪的旧消息不尝试恢复。
- Session 为空时显示界面欢迎消息：

      你好，我是 Steve Code。有什么需要我帮忙的？

- 欢迎消息不写入 Session。

## 滚动行为

- 用户位于底部时自动跟随流式回复。
- 用户向上查看历史后停止自动拉回。
- 新内容到达时显示“回到最新消息”。
- 点击后恢复自动跟随。
- 分批收起视口上方的旧 Turn 时使用滚动锚点补偿，不改变用户当前看到的内容位置。

## 输入行为

- Enter 发送。
- Shift+Enter 换行。
- 中文输入法组合期间 Enter 不发送。
- 输入框从一行扩展到最多三行。
- 字号至少 16px，避免 iPhone Safari 自动缩放。
- Turn 运行时输入框完全禁用。
- 文件上传期间允许继续编辑文字，但发送按钮保持禁用，Enter 也不触发发送；上传完成后附件进入待发送区。
- 连接成功后的空闲状态自动聚焦；Turn 完成、停止或发送失败后恢复聚焦。
- 不支持提前输入、草稿等待或消息排队。

## 发送与停止

- 空闲时显示“发送”按钮和附件按钮。
- Turn 运行时发送按钮替换为红色“停止”。
- 附件按钮同时隐藏。
- 点击停止不二次确认。
- 收到 `aborted` 后显示“已停止”。

## 附件

- 使用回形针按钮选择文件。
- 支持多文件。
- 选择后立即上传。
- 输入框上方显示附件卡片。
- 上传期间在附件区显示带 spinner 的聚合状态卡片：单文件显示文件名，多文件显示文件数量；成功后替换为普通附件卡片，失败后移除。
- 发送前可移除卡片，但不删除 workspace 文件。
- 允许仅发送附件。
- 没有正文时自动使用“请查看我上传的文件”。
- 复用现有 `Uploaded files` Prompt 格式。
- 历史渲染时隐藏技术前缀并还原附件卡片。
- 首版不做拖拽、粘贴、缩略图、上传百分比或确定进度条。
- 接受文件名包含逗号时解析不完美的边缘情况。

## UI 请求

- `confirm` 使用“确认”和“取消”。
- `select` 使用可点击选项。
- `input` 使用单行输入。
- `editor` 使用多行输入。
- 统一使用居中弹窗。
- 已知授权、计划、工作区信任和模型选择提示转换为面向普通用户的中文文案；提交时仍使用原始选项值。
- unified diff 和授权提示中的原始命令保留原文，使用等宽字体、不换行、横向滚动且隐藏滚动条。
- 只有发起 Turn 的页面可以回答。
- 其他页面显示“正在等待另一页面完成确认”。
- 回答请求提交后立即禁用当前弹窗中的全部控件，避免重复提交；提交失败时保留弹窗并恢复操作。

## 失败处理

- 用户消息先乐观显示。
- 提交失败后标记“发送失败”。
- 文字和附件恢复到输入区。
- 不自动重试。
- Server 重启导致 `session_not_found` 时，静默重新挂载 Session 并重发原消息；只有恢复失败才显示断线提示。
- 提交遇到 `409` 时，用户消息标记为“发送失败”，并提示“Steve Code 正在处理其他消息，请稍后重新发送”；原内容恢复到输入区，要求用户主动重发。
- Turn failed 显示“这次没有处理成功，请重试。”
- 单次工具调用失败不显示整轮失败；只有最终 Turn 状态为 failed 时才按失败处理。
- 授权被拒绝时显示“你未授权这次操作，未做任何修改。”，不显示“未能完成”。
- Extension Error 显示“处理过程中出现了问题，请重试。”
- 上传过大显示“文件太大，无法上传。”
- 其他上传失败显示“上传失败，请重试。”
- 初始化失败显示“暂时无法连接 Steve Code，请稍后刷新页面。”
- 不显示 HTTP 状态码、内部错误名或堆栈。
- `ui_event notify` 使用浅色系统消息显示原文。

## 断线恢复

- 断线时显示“连接已断开，正在重新连接”。
- 输入、上传和 Stop 暂时禁用。
- 自动恢复原 Session。
- 自动重连不重新请求 `messages`，不清空或重建消息 DOM。
- 自动重连保留当前已渲染内容、自动跟随状态和滚动位置，只恢复 Session 并继续接收新连接建立后的 SSE 事件。
- 页面在 Turn 运行期间，或因锁屏、切换 App、切换标签页而长时间进入后台后，再次变为可见时主动关闭旧 SSE，重新挂载 Session，以当前 `messages` 历史受控重建时间线并打开新 SSE，及时补齐后台期间的最终消息；短暂切换继续沿用普通重连语义，避免干扰系统文件选择器等临时界面。
- 后台恢复的历史同步保留用户原有的自动跟随状态；位于底部时回到最新消息，正在查看历史时保留原滚动位置。
- 页面首次连接到正在运行的 Session 时，将 SSE 中的当前 Turn 与历史最后一个匹配的用户消息绑定一次；后续去重只依据 Turn ID，不再用消息文字判断。
- 如果重新挂载后的 Session 已经空闲，使用 Session 状态解除页面遗留的运行态、输入禁用和输入动画；不补齐断线事件，也不重建消息 DOM。无法确认终态的工作过程显示为“状态未同步”。
- Safari 从文件页返回和 BFCache 恢复仍不重建历史，保留浏览器恢复的页面与滚动状态；它们与锁屏或切换 App 后的可见性恢复区别处理。
- 明确接受断线期间的消息、工具过程或文本增量可能缺失；自动重连不尝试补齐。
- 用户手工刷新页面时重新加载完整当前历史，并将它作为权威同步结果。
- 采用以上区分是为了避免历史重建与旧的或迟到的 SSE 回调、新连接增量及 `completed.output` 相互叠加，造成短句重复、回复回缩或滚动位置跳动。
- `completed` 到达时，只有当前回复文本是 `event.output` 的前缀时才用完整输出补齐；文本不一致时不覆盖现有气泡，也不把 `completed.output` 用作断线缺口的强制同步机制。
- 不提供手工重连按钮。
