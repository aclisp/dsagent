# 微信 iLink 通道首版

状态：已实现，已完成自动化及主要真实微信验收（2026-11-10）。腾讯参考源码：`Tencent/openclaw-weixin@0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e`（3.0.0-beta-0）。

## 范围

- 每个部署使用一个有效微信绑定，只接收扫码者本人的单聊；缺少绑定者身份时拒绝启动。
- 沿用共享 Session、来源 alias 和 busy 规则；与 wecom 和 Web UI 同属一个部署信任域。
- 文本、图片和文件双向收发；语音仅消费微信提供的转写，没有转写时提示改发文字。视频后置。
- 附件起始的连续输入在提交前短暂合并，纯文本立即提交；执行期间的新请求仍返回 busy，不排队。
- 处理期间维持输入状态，所有终态都清理；完成回复结果，失败和中止回复固定简短通知。
- 终端扫码登录，支持手机验证码、二维码刷新和服务端重定向；保存后手动重启服务，不做凭据热加载。
- 记录收发消息的服务端 ID、正文和已落盘附件路径，支持持久化引用还原；未命中明确标注不可用。
- 支持定时任务 source 投递，持久化 context token；服务端仍接受 token 是投递前提，不保证永久可达。
- 本次新附件准备失败时整批暂不提交 Agent，并告知重发；历史引用不可用只标注缺失。
- 游标与入站消息原子落盘。恢复尚未提交的消息；在提交前记录 admission，重启后对提交结果不明或执行中请求标记中断，不自动重跑。
- 临时投递错误有限重试，按稳定投递 ID 保留进程内分片和附件进度；不重发已确认成功的部分。
- 永久文件投递失败或重试耗尽时通知；进程重启后不补发已有回复或文件，不建立持久化 outbox。
- 选择性移植腾讯协议基础代码和相关测试，移除 OpenClaw 运行时依赖，保留来源及许可证。

## 集成

新增独立 `packages/wechat`。通用 Chat Client 提供可选的提交前持久化、任务生命周期和稳定投递 ID 接口；wecom 默认行为保持。媒体产物提取和私密链接脱敏复用通用工具。

凭据、入站日志、游标和引用索引保存在 DSCode home 的通道私有目录；上传文件继续使用 workspace 的 uploads，索引清理不删除 workspace 文件。更换绑定按账号和用户隔离状态。

## 验收

自动化验证协议字段、uint64 ID、超时取消、密钥编码、owner 校验、持久化与恢复、合并/busy、引用、所有任务终态和部分发送重试，并回归既有通道行为。真实微信验证登录、文本、语音转写、图片/文件、引用、定时回投及重启恢复。

真实联调需要使用者扫码、输入手机验证码并操作微信客户端。未完成真实微信验收前不声明首版可正式使用。

实际验收与限制记录在 `docs/WECHAT_ACCEPTANCE.zh-CN.md`。引用标识同时兼容 svr_id 和嵌套的 message_item.msg_id；引用缺失不会凭内容猜测对应消息。
