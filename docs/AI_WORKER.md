# AI Worker 产品需求

本文只记录 AI Worker 的产品能力、用户可见规则和验收约束，不记录实现步骤、代码结构或
Slice 开发历史。启动、配置、部署和日常使用说明见 [packages/web-ui/README.md](../packages/web-ui/README.md)。

## 产品定义与范围

- 数字员工是一个拥有工作能力和持续记忆的 Agent 服务实例。
- 用户可以让数字员工立即工作，也可以安排一次性提醒或周期性工作。
- 定时任务触发后使用数字员工已有的工作能力和会话记忆完成任务，并把结果保留在共享会话中。
- 接入 IM 后，用户可以在群聊中 @数字员工发起工作、管理任务或接收指定任务的结果。
- 首期真实 IM 通道为企业微信智能机器人；通用外部事件触发、语音/视频等未列明的媒体消息和其他 IM 平台不在首期范围。

## 入口、会话与权限

- 一个 workspace 只激活一个共享会话；普通 Web UI、诊断 Web UI、IM 和定时任务使用同一会话上下文。
- 服务启动时不主动激活会话；首次打开页面、收到群聊请求或任务到期时才加载或创建会话。
- 普通用户通过 `/chat/<workspaceId>` 与数字员工对话；诊断人员通过 `/debug/<workspaceId>` 查看底层过程。
- 普通 Web UI 不展示内部任务 ID、Cron 表达式、run 元数据或协议标记；诊断 Web UI 保留原始事件和技术信息。
- 普通 Web UI 发起的请求不自动发送到群聊；群聊请求和被设置为群聊投递的任务才允许发送群消息。
- 每个服务实例首期绑定一个固定群聊。固定群之外的群聊、单聊和未绑定的 workspace 不触发数字员工。
- 群成员资格和使用权限由 IM 平台管理；数字员工不另行维护成员白名单。
- 群内成员可以使用数字员工的全部能力，包括创建、修改、暂停、恢复和删除定时任务。

## 定时任务能力

### 用户能力

- 支持一次性任务和周期性任务；两种任务都可以选择：
  - `session`：结果只保留在共享会话中，仅在 Web UI 查看；
  - `group`：结果保留在共享会话中，并在绑定的群聊中发送。
- 投递范围与任务类型相互独立：一次性任务和周期任务都必须完整支持两种投递范围。
- 用户通过自然语言表达任务内容、时间、周期和投递范围；Agent 负责把意图转换为任务配置。
- 时间、任务内容或投递范围有歧义时，Agent 必须先追问；确认时使用实际时间或自然语言周期，以及“仅在 Web UI 查看”或“同时发送到群聊”等表述。
- 普通用户不需要了解内部任务 ID、Cron 表达式或运行元数据。
- Agent 修改任务后，必须确认配置已被调度器接受，才能向用户报告成功。

### 任务规则

- 周期任务只接受 Croner 原生 Cron 语法，不定义额外方言；支持 Croner 提供的 5、6、7 段及其名称、昵称和扩展语法。
- 所有周期任务使用服务实例的 IANA `TZ` 时区；不为单个任务保存独立时区。
- 一次性任务使用带 `Z` 或显式偏移量的 RFC 3339 时间。
- 相邻两次实际周期触发时间不得少于 5 分钟。
- 任务数量最多 100 个，单个任务提示词最多 32 KiB；任务 ID 最长 64 个字符，只允许小写字母、数字和连字符。
- 任务定义无效时整份拒绝，不部分加载、不自动修正；运行中的上一份有效定义继续生效。
- 周期模式不再产生未来时间时，任务保留但自动停止并标记为已耗尽；一次性任务成功消费到期点后停止，任务记录仍保留。
- 用户看到的任务状态是有限的当前运行、最近运行和最近跳过摘要，不承诺完整的历史记录。
- 修改任务内容、时间、类型或投递范围后，旧定义的运行快照不能被新定义继承；暂停、恢复和删除必须立即影响后续触发。
- 服务重启、关机、休眠或事件循环阻塞期间错过的触发不补跑。一次性任务只能消费一次，周期任务只等待下一个未来触发点。
- 回调延迟超过 60 秒视为迟到并跳过；不为了补偿迟到而执行旧 occurrence。
- 同一个周期任务上一轮仍在提交或执行时，下一次触发直接跳过，不排队；Agent Turn 结束后解除重叠保护，群聊投递重试不阻塞下一轮。

### 执行与失败

- 任务通过与普通请求一致的数字员工工作流程执行，并共享同一会话记忆。
- 定时任务没有浏览器所有者。需要 `confirm` 时拒绝；需要 `select`、`input` 或 `editor` 时取消，不能等待人工输入。
- 不抢占正在执行的人工工作。人工请求撞上忙碌状态时直接丢弃，并明确提示用户稍后重新发送。
- 任务提交失败时立即尝试，之后最多重试 5 次，间隔为 10、20、40、80、160 秒并加入有限抖动；确定性错误不重试。
- occurrence 采用 at-most-once 语义，不承诺 exactly-once 或 at-least-once。已接受的 Turn 不自动重新运行。
- Agent 执行失败、被中止、提交失败、重叠、迟到或群聊最终投递失败时，不向群里发送失败通知，避免周期性刷屏；用户可在 Web UI 查看状态，或之后主动询问数字员工。
- 没有可用 IM Provider 时，`group` 任务仍然执行并保留结果；本次群聊投递标记为不可用，不排队、不补投，也不自动改成 `session`。
- 群聊投递失败不改变数字员工工作的执行结果；服务重启后不恢复未完成的投递。
- 不设置 Agent Turn 的自动超时；卡住的工作由用户在 Web UI 手工停止。

## 普通 Web UI 的来源呈现

- 普通 Web UI 面向非技术用户，使用聊天式的移动优先布局；详细界面规范见 [PRIVATE_CHAT.md](PRIVATE_CHAT.md)。
- 群聊产生的用户消息仍显示在共享会话中，但使用“群聊”来源标记，并在有发送者名称时显示名称；不把群聊内部协议前缀直接展示给普通用户。
- 定时任务产生的用户行显示为居中的“定时任务”事件卡；不显示任务 ID、Cron、投递范围或 run 元数据。
- 数字员工输出按普通聊天消息展示；完整工具调用、原始事件和调试字段只在诊断 Web UI 中查看。
- 私有的 `session` 任务只在 Web UI 可见，不产生群聊消息；这项能力不依赖 IM 是否配置。

## 企业微信通道

- 企业微信接入是可选能力；未配置时，Web UI 和定时任务仍可独立使用。
- 只有固定群中带有真实 mention 的文本、图文混排消息或支持的引用媒体消息，且用户通过企业微信输入框的 @ 选择器插入数字员工的真实 mention，才会触发请求。
- 可见文本中出现 `@数字员工` 并不等于平台 mention：直接粘贴带有 `@BOT_NAME` 的普通文本不会产生企业微信回调，数字员工不会收到也不会处理这条消息。
- 对已经收到的有效文本或图文混排回调，mention 可以出现在文本任意位置；交给 Agent 前去掉该 mention。`BOT_NAME` 是必填配置，用于精确识别。
- 群聊图文混排中的图片，以及群聊中引用的图片或文件，会立即下载到 workspace 的 `uploads/` 目录，并以与普通 Web UI 相同的附件 Prompt 形式交给 Agent；下载失败时仍创建 Turn，并把失败信息交给 Agent。
- 独立的群聊图片/文件消息不保证产生企业微信回调；首期不承诺处理这类消息。单聊、其他群、机器人自己的消息和未带真实 mention 的消息静默忽略。
- 用户消息的最终文字回复回到原始群消息；定时任务的群聊结果作为群内新消息发送。Agent 在最终文字中明确引用的 workspace 文件可以作为原生图片或文件附件追加发送；文字交付优先，附件失败不重试文字或额外通知群聊。
- 首次配置时可以先通过一次性的发现流程取得目标群 ID；发现流程只输出群 ID，不创建会话、不调用 Agent、不回复消息、不写入配置。
- 企业微信凭证只能用于通道连接和投递，不得进入 Prompt、会话、任务配置或日志。
- 企业微信入站媒体受 `MAX_UPLOAD_BYTES` 限制；出站只发送 Agent 明确引用的 workspace 文件，单次最多 5 个且受企业微信媒体上传大小限制。`uploads/` 文件沿用 workspace 文件的持久化策略，不在首期自动清理。

## 安全、隐私与可观察性

- workspace 地址是访问凭证；只有持有完整高熵地址的用户才能打开对应 Web UI。
- Agent 输出、Prompt、凭证、发送者姓名、完整群 ID 和 workspace ID 不写入普通生命周期日志或用户可见状态。
- 配置错误只说明字段路径和原因，不回显敏感字段值。
- 群聊失败不通过额外通知放大；共享会话和诊断界面保留足够信息供用户主动检查。
- 产品不提供独立的任务管理后台或通用外部事件入口；任务管理通过已有 Web UI/IM 对话完成。

## 验收标准

- 用户能在 Web UI 和绑定的企业微信群中，用自然语言创建、修改、暂停、恢复和删除一次性或周期任务。
- `session` 与 `group` 两种投递范围在一次性和周期任务上行为一致，区别仅是是否额外发送群消息。
- 任务在共享会话中执行，重启和错过触发不会导致补跑或重复执行；重叠、迟到和忙碌行为符合上述规则。
- 普通 Web UI 能区分普通消息、群聊消息和定时任务；诊断 Web UI 仍能查看完整原始过程。
- 企业微信只有真实 @ mention 才触发，复制粘贴的可见 `@BOT_NAME` 不触发；有效消息能正确回复，定时群聊结果能作为新消息发送。
- 企业微信群聊 mixed 图片和支持的引用图片/文件能进入共享会话；Agent 明确引用的图片/文件产物能作为群聊原生附件发送，独立群聊文件未产生回调时不产生虚假处理结果。
- 失败结果不会造成周期性群聊刷屏；用户可以通过 Web UI 或后续主动询问获得状态。
